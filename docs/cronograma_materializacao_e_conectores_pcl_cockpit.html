2. Linha do Tempo e Sequência Técnica de Execução

Princípio de Precedência Técnica: Não é viável integrar suítes corporativas (Google Drive, Microsoft Teams, ClickUp) sem dispor previamente de um servidor de retaguarda independente e um fluxo seguro de Login OAuth2 com Cofre Cifrado para armazenamento de chaves e permissões.

3. Detalhamento dos Marcos Operacionais

Marco M0 — Fundação: Servidor Independente e Tabelas de Banco (SQL 003)
Duração estimada: 2 a 3 dias

Cenário Atual: Todas as rotas de backend (/api/aeos/*) rodam dentro do servidor de desenvolvimento do Vite (vite.config.ts), incapaz de gerenciar sessões longas, autenticações OAuth ou filas de processamento.

Entregas:

  • Subida e sincronização do pacote Gate 2 no GitHub (Docker, Laya e Caddy prontos).
  • Criação do serviço de backend dedicado em Node (Fastify/Express) na pasta server/, desacoplando a API da interface gráfica sem alterar o visual em :3001.
  • Execução da Migração SQL 003 no PostgreSQL 17 para criar as tabelas de: usuários, credenciais, sessões, orçamentos FinOps, trilha SHA-256 encadeada e cofre de conectores cifrados (AES-256-GCM).
Critério de Aceite: O Cockpit responde normalmente em :3001 com as APIs rodando no servidor autônomo; npm run verify:all atinge 100% de sucesso.
Marco M1 — Identidade Real e Trava Física de 2 Dispositivos
Duração estimada: 3 a 4 dias

Cenário Atual: A tela de login cria dados simulados no localStorage; a aba Segurança & Sessões exibe selos e dispositivos ilustrativos.

Entregas:

  • Autenticação real com senhas protegidas por hash forte (Argon2/Bcrypt) e cookies seguros (HttpOnly).
  • Integração OAuth 2.0 / 2.1 com PKCE para login direto com: Google, Microsoft Entra ID, GitHub e LinkedIn (OpenID Connect oficial).
  • Bloqueio físico do 3º dispositivo: Caso o usuário tente acessar por um terceiro navegador, o backend bloqueia o acesso e exibe a tela de revogação de sessões ativas com derrubada em tempo real.
Critério de Aceite: Login via Google ou Microsoft entra com nome e foto reais; login em 3 navegadores distintos bloqueia o terceiro imediatamente até revogação.
Marco M2 — Inteligência Conectada, FinOps Hard Lock e Auditoria Imutável
Duração estimada: 4 a 5 dias

Cenário Atual: O Laya no chat usa regras estáticas de JavaScript; a busca web responde apenas dados fixos; FinOps e Auditoria ISO operam com números fictícios.

Entregas:

  • Laya Neural no Chat: O chat passa a consultar a API física do Laya (porta :20140) em CPU INT8 para classificar intenções e verificar contradições documentais em 25ms.
  • Busca Web Real: O botão "Web" executa buscas reais via conector configurado (Brave Search / Tavily) com links verdadeiros em pílulas retráteis.
  • Memória Vetorial Permanente (PGVector): Documentos anexados em #documentos são vetorizados e preservados no banco (não somem ao teclar F5).
  • FinOps Hard Lock Real: O consumo de tokens é registrado no banco; se o teto de gastos configurado na Aba 4 for atingido, o backend bloqueia chamadas pagas e redireciona automaticamente para o Ollama local (custo $0.00).
  • Auditoria Encadeada SHA-256: Cada login, alteração de orçamento e consulta é gravada no banco encadeando o hash do registro anterior, permitindo conferência matemática de integridade.
Critério de Aceite: Reduzir o teto de gastos no FinOps para $0.01 bloqueia chamadas em nuvem de imediato; conferência na Aba 7 atesta integridade dos registros via SHA-256.
Marco M3 — Protocolo MCP Remoto Seguro & Conectores Externos Consagrados
Duração estimada: 6 a 8 dias (dividido em M3.1 e M3.2)

As 5 Travas de Segurança Obrigatórias para Conectores Externos:

  1. Apenas Servidores Oficiais ou Código Aberto Auditado: Foco em servidores homologados pelas próprias empresas mantenedoras.
  2. Cofre Criptografado no Servidor (AES-256-GCM): Chaves de acesso e refresh tokens nunca tocam o navegador nem arquivos públicos.
  3. Protocolo MCP Moderno (Streamable HTTP): Comunicação direta com renovação automática de credenciais via OAuth 2.1 PKCE.
  4. Menor Privilégio: Solicitação estrita dos escopos essenciais de cada ferramenta.
  5. Human-in-the-Loop (Trava Humana Obrigatória): A IA pode consultar e ler dados autorizados, mas qualquer envio externo ou exclusão exige cartão de aprovação do usuário com 1 clique.

Marco M4 — Ações Vivas no Chat, Voz Real, Reuniões e Orquestração DAG
Duração estimada: 5 a 6 dias

Cenário Atual: Microfone devolve texto fixo; criação de agentes No-Code não persiste no backend; abas de Reuniões e Fluxos funcionam apenas como protótipos de interface.

Entregas:

  • Microfone Real: Gravação direta de áudio pelo navegador com envio ao backend para transcrição neural real.
  • Ações "@Sistemas" no Chat: Digitar @Gmail, @ClickUp ou @Teams aciona ferramentas reais; clicar em "Confirmar Envio" despacha o comando efetivamente.
  • Persistência de Agentes e Skills: Agentes criados no Criador No-Code são gravados no banco e podem ser invocados no chat (ex.: @AnalistaFinanceiro).
  • Reuniões com Despacho Automático: Upload de áudio/vídeo real ➔ transcrição neural ➔ extração automática de plano de ação ➔ geração e envio de tarefas para o ClickUp ou Jira.
  • Executor de Fluxos Visuais (DAG): O botão "Executar" dos fluxos encadeia operações reais (Exemplo: Ao detectar novo e-mail no Outlook ➔ Resumir via IA ➔ Criar pendência no ClickUp ➔ Notificar no Teams) com trilha de auditoria para cada nó do grafo.
Critério de Aceite: Subir áudio real de reunião e constatar a tarefa criada de verdade dentro do workspace do ClickUp; executar fluxo entre duas ferramentas com log de sucesso no PostgreSQL.
Marco M5 — Polimento Visual v4 (Opcional) & Go-Live Homologado na VPS
Duração estimada: 2 a 3 dias

Cenário Atual: Toda a infraestrutura de deploy (Docker Compose, Laya INT8, Caddy com HTTPS automático) já está desenhada e validada no Gate 2.

Entregas:

  • Seleção e integração dos elementos visuais desejados dos protótipos v4 (organização de menus por departamentos, monitor de latência e rótulo de versão).
  • Subida assistida na VPS com certificado SSL/HTTPS emitido automaticamente pelo Caddy.
  • Habilitação de rotina de cópia de segurança automatizada (Backblaze B2 ou Cloudflare R2).
Critério de Aceite: Acesso seguro via domínio oficial HTTPS com todas as 5 baterias de teste (verify:all) reportando zero inconformidades.

5. Decisões de Liderança Requeridas Antes do Início

Para darmos início ordenado à execução do Marco M0/M1, submeto à sua validação 4 diretrizes:

1. Checkpoint Seguro no GitHub (Gate 2) Deseja realizar o commit e push das alterações validadas do Gate 2 (empacotamento Docker, configuração Caddy e Laya INT8) nos repositórios oficiais antes de iniciarmos as migrações do Marco M0?
2. Priorização dos Conectores Externos na Onda M3 Aprova dividirmos o Marco M3 em duas ondas, priorizando na Onda M3.1 a tríade de produtividade central (Google Workspace + Microsoft 365 + ClickUp + GitHub), deixando HubSpot, Atlassian, RD Station e LinkedIn API para a Onda M3.2?
3. Diretriz de Blindagem e Segurança no LinkedIn Confirma a adoção estrita do OpenID Connect Oficial para autenticação e da API REST Oficial (descartando qualquer automação por cookie ou navegador não homologada que possa comprometer a integridade de contas corporativas)?
4. Estratégia de Identidade Visual (v3.9 vs. v4) Prefere preservar a interface estável atual enquanto construímos o motor real de retaguarda (M0 a M3), reservando o polimento estético da versão v4 para o Marco M5?
Protocolo de Governança PCL-AEOS: Nenhuma alteração de código ou migração de banco será realizada sem o seu aval formal para as quatro diretrizes acima.
